# 2026-09-30 — Sound fixed

## Summary

Sound was working technically but was inaudible in practice. Now it plays at normal game levels on
the output the user actually listens to.

## What was wrong

- The game follows the system default output, which was the Arctis Nova Pro USB headset. The user
  listens on the motherboard's Ryzen HD Audio analog output (ALC1220).
- Effects were mixed quietly: −30 to −20 dBFS for most tones, about −29 dBFS for the hyperdrive drone.
- Nothing played at startup (the ship starts at 0% throttle), so silence looked like broken audio.

## Changes

- System default output switched to Ryzen HD Audio analog (`wpctl set-default 57`), at the user's
  choice. This is system-wide and applies to every app.
- Levels raised to about −16 to −8 dBFS, then master lowered to 0.5 (−6 dB) and later 0.25 (−12 dB total, about −28 to −20 dBFS) after the user found it too loud twice. The game applies `sound::VOLUME` at startup. Other levels: event tones 0.25–0.3, UI clicks 0.15, drone ×1.6,
  crash noise 0.6 (with soft clipping).
- Launch fanfare when the game starts, so working audio is audible immediately.
- The audio device, host and format are logged at startup.
- Dev tool: `UNIVERSE_SOUND_TEST=1` plays every sound in an 11-second sequence, for checking levels.
  Record it with `parec -d "$(pactl get-default-sink).monitor" --format=float32le --raw`.
