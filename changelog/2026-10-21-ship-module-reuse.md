# Reuse existing modules before ship arrangement

The explorer fit-out study created custom furniture before discovering the
existing modular system. The owner corrected that order: discover applicable
products and their placement consumer before sizing the aisle, cabin or cockpit.

Adds `ship-artifact.module-inventory` and `ship-rule.module-reuse` using existing
workflow schemas. G3 now requires inventory, ownership and consumer evidence;
spatial-layout, build-input, assembly and inhabitation definitions carry those
requirements. Pilot seat/console products are included. References retain their
actual envelopes and transforms, with one physical instance and BOM owner.
Reservations stay non-exported; missing products/models/consumer support become
explicit Registry/Ships gaps, never permission to fabricate a substitute.

Floors are not an exception to ownership: current editable deck polygons are
walking architecture, not stocked deck-panel/shoe/clamp installations. Explicit
stock structure remains distinct. No lining/holder layer is inferred; coincident
hull/deck floors and baked equipment are rejected by the review procedure.

Independent audit verified seven discovered equipment record/manifest/model
hash chains, all unselected, and reran nine project declaration cases. The actual
explorer arrangement remains blocked pending real product allocation, pilot
station replacement, ownership and consumer/fit/access evidence. The project
checks do not prove mesh ownership, geometry, mounting or runtime behavior.

Audit: `docs/diagnostics/ship-module-reuse-audit-20261021.yaml`.
All 47 registry regressions pass. Runtime schemas and ship instances are unchanged.
Full registry checks and four affected page/link checks pass; the inventory page
was visually inspected. There are now 94 workflow definitions. Existing report
gaps are unchanged.
